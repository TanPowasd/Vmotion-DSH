# 通用创作、性能与转场批次

本批同时扩展通用视觉组合、共享渲染效率及 Agent 性能反馈。用户最新要求是广度、高性能和优化；音频只收敛已实现的增量，不把它作为全部产品主线。软件不调用模型，外部 agent 继续通过文件/SDK/CLI/MCP 创作。

## 编译和画布复用

组件运行缓存现在记录实际导入文件及解析时不存在的候选路径。修改无关组件/JSON 不会重编当前组件；修改被导入资源、增加优先匹配的模块文件或改变 SDK 入口会失效。Worker LRU 最多 12 个，每个 128 MiB 堆上限；被淘汰 Worker 的依赖记录一起清理。运行代码的输出不做帧缓存，有状态错误仍可检测。

类型检查缓存同时追踪被读取 JSON、缺失文件和目录解析。修复了 TS 源码不变但 JSON 类型变化时错误复用旧诊断的问题；候选源码和 JSON 使用固定快照，不退回读取旧磁盘版本。无 TypeScript 的工程直接跳过编译器初始化。

临时效果画布使用有界池：按尺寸复用，重新获取时重置像素、变换、保存的裁剪、透明度与样式；最多保留 96 MiB，关闭渲染器释放。现有 256 MiB 活跃效果画布预算继续执行，保留池不是总进程/显存限额。`surfacePoolMb=0` 提供同画面的不保留基线。

## 性能取证

`render_profile` 可查询场景、序列、独立组或存储候选，最多 8 个帧、4 轮，提供：

- 首次、平均、p50/p95 与后续轮平均渲染耗时；PNG 编码可选单独计时。
- 组件编译/复用、类型检查次数，画布分配/复用/保留字节与预算。
- 数字求值/组件时间、图层绘制调用及时间/节点图像素工作。
- 相同帧的真实像素 hash 与状态代码差异；默认只返回摘要，detail=true 返回逐轮记录。

测试图像 hash 和传输时间不计入 renderMs，外部 RPC、播放器、GPU/显示器与声音准备也不包含其中。独立页可能在尺寸解析时预先求组件，所以此数据不是所有启动开销。数值来自当前机器和场景，不是正式参考设备实时预览、4K 或两小时验收。

实际二维 MCP 场景在 640×360、9 个样本中，池分配 4 次、复用 26 次；基线分配 30 次。两者逐帧 hash 完全相同，开发版当次热渲染均值约 3.09/3.84 ms。二维数学/原生三维示例在 1280×720 下热均值约 25.48/25.52 ms，差异很小；收益主要是分配从 36 次降为 5 次，不宣称所有场景都有显著加速。导出尺寸/画质没有被降低。

## 通用转场和合成

SDK `sceneTransition` 与 `transition_plan` 支持 crossfade、slide、push、wipe、iris、zoom、dip、cut。可配置方向、起始/时长、颜色及双方内容时钟的 offset/rate，source repeat=clamp；源码保持参数化。

`Node.isolation=true` 让图层组在透明面上先合成，再与父级合成。`blend="lighter"` 为预乘 Alpha 加法；crossfade 对 A/B 分别加权后在隔离组相加，避免用两个 source-over 淡化导致中间变暗或透明度错误。端点保留源画面，圆形遮罩和中间色辅助图层在终点不会盖住 B。此路径按现有 SDR/Skia 色彩空间合成，没有新增线性/HDR 色彩管理。

```ts
sceneTransition({ id: 'mix', fromSceneId: 'math', toSceneId: 'space',
  progress: .5, width: 1920, height: 1080, style: 'iris',
  fromOffset: 0, toOffset: 20, fromRate: 1, toRate: 1 });
```

Agent 使用 `transition_plan` 批量创建新的场景及组件，源场景保持可编辑；可在指定视频轨道/帧插入并显式延长序列。不会自动裁切、滑移或波纹调整原片段。组件 `sceneDependencies` 声明固定场景引用，参与缺失/循环检查；任意其他 TS 组件也可声明动态引用的依赖。未声明的任意代码引用仍以运行画面检查为准。

一批最多 16 个转场，候选默认采样最多 12 张；coverage.incomplete 时需要补充预检。原样 project_apply 共享一次撤销。可用 render_profile planId 在保存前测准确候选；结构、像素和性能分别有证据，不能互相替代。

## 已收敛的声音增量

序列可声明 `mix`：轨道/总线/主输出的 EQ/效果、gain/pan 秒级自动化、后推子 send 和立体声联动峰值侧链 ducking。路由与侧链组成同一 DAG，反馈拒绝；锁定轨道的直接混音修改被拒绝。主输出可使用 EBU R128 测量后的常量增益，或两遍 loudnorm 动态标准化；linear 模式目标不可同时满足时明确报错，auto 可选择动态处理，并测量最终结果。

`audio_mix_inspect/plan` 返回短配置及准确候选；`audio_preview planId` 试听混音候选；`audio_audit` 按 FFmpeg BS.1770/R128 测实际 LUFS、LRA、true peak，返回范围覆盖和 profile 差异。静音/过短范围显示不确定性；有损交付应再测编码文件。指标不证明听感，也没有录音、VST、完整 DAW。

效果从起点处理并缓存，随机范围沿用历史状态；子序列先处理自身混音，再经过父级裁切、变速、音量/淡化。缓存仅根据声音子图和素材版本失效，修改画面不重做声音。处理使用固定分块与磁盘 stems，默认 scratch 20 GiB、最多 64 轨/16 总线/两小时/64 MiB 效果状态；预算可显式修改，不是整个项目缓存配额。未配置混音的原时间轴仍沿用 ±0.95 安全限制；配置新混音保留浮点超幅证据，需要明确 limiter/normalization。整段声音标准化不以采样摘要替代。序列 `mix.master.gainDb` 默认在主效果之前（`gainStage:"pre"`），主 limiter 为最后一级；`gainStage:"post"` 恢复旧顺序。

便携包内 `resources/app/examples/workstation-lab` 为 8 秒 1280×720/30fps、240 帧的数学二维/原生三维与八种转场例子，提供可编辑源码、contact 与性能 JSON。
